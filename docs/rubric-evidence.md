# Rubric and evidence checklist

| Requirement | Implementation | Evidence |
|---|---|---|
| One domain and category | Fictional e-commerce support; NLP | Report introduction and workplace scenario |
| At least three cohesive sub-tasks | Intent, sentiment, summary and grounded QA | Ticket workspace and policy-chat screenshots/video |
| API-driven interactive app | Streamlit -> FastAPI -> local models | Running app, `/docs`, request/response examples |
| Actual fine-tuning | Full DistilBERT encoder and 27-class head trained on Bitext | Saved safetensors, trainer state, manifest, curves and held-out metrics |
| RAG using domain documents | Eight synthetic policy PDFs; MiniLM retrieval; Qwen answers | Document manifest, retrieved pages, cited answers, unsupported-query cases |
| Anchor | Individually describe a workplace or industry analogue | Each member's individual Part IV |
| Apply | Demonstrate tasks and chatbot on representative tickets | Actual outputs and policy sources |
| Analyse | Interpret actual metrics, efficiency and prototype gaps | Public vs independent-ticket scores, review worksheets, measured timing if completed |
| Reflect | Constraints and one justified priority improvement | Distinct member sections; each member reviews and personalizes their own reflection before submission |
| Contributions | Names, BITS IDs, descriptions, percentages totaling 100 | Group metadata and report cover |
| Report | Matching Word/PDF exports, screenshots, citations | Per-member `<groupid>` reports |
| Video | Student screen recording with the presenter's own explanation | Final Google Drive link and evaluator access check |
